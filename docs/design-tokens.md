# Design Tokens — AcademicSpace (v1.0, финализировано в Фазе 0)

Извлечено из `design-reference.html`, сверено с пользователем и
зафиксировано в коде: `theme/tokens.ts` (палитры/шрифты/радиусы/отступы/
тени) + `constants/brand.ts` (брендинг/лого). Все три открытых вопроса
v0.1–v0.2 закрыты (см. раздел «Закрытые вопросы» ниже).

Десктоп-адаптация в этом файле сознательно не рассмотрена — см.
`CLAUDE.md` §9, отдельная фаза после полностью готового мобильного
фронтенда.

## Шрифты
- **Заголовки / display**: `Unbounded` — начертания 500/600/700,
  используется с `letter-spacing: -0.02…-0.03em`
- **Основной текст / UI**: `Manrope` — начертания 400/500/600/700/800

## Тема: светлая/тёмная — теперь настоящий переключатель

В дизайне появился тумблер «Тема оформления» (экран Settings) и
7 семантических токенов, у каждого — пара light/dark значений:

| Токен | Light | Dark | Назначение |
|---|---|---|---|
| `theme.page` | `#EDEDF1` | `#0B0D22` | Фон вне контента (canvas/статус-бар зона) |
| `theme.screen` | `#F6F7FB` | `#12142E` | Базовый фон контентных экранов |
| `theme.card` | `#FFFFFF` | `#1B1E45` | Фон карточек |
| `theme.border` | `#E7E9F2` | `rgba(255,255,255,.08)` | Обводка карточек |
| `theme.ink` | `#1B1F4B` | `#EDEFFA` | Основной текст |
| `theme.sub` | `#7A7F9E` | `rgba(255,255,255,.55)` | Вторичный текст |
| `theme.chip` | `#F4F5FA` | `rgba(255,255,255,.07)` | Фон чипов/мелких плашек |

Брендовые акценты (`accent.blue` `#2E6BFF`, `accent.gold` `#F3C24B`,
`accent.green` `#1FB574`, `accent.rose` `#E2739B`, `accent.blueLight`
`#7C93FF`) **не меняются между темами** — это осознанное решение самого
дизайна, переноси как есть.

Стейт хранится как `dark: boolean` — в RN-реализации это `theme` в
Zustand (`'light' | 'dark'`), персистентный через AsyncStorage,
переключается свитчем в Settings (тот же паттерн `sw()`/`knob()`, что и
у остальных тумблеров в прототипе).

### ⚠️ Важно: тема применена не везде — это нормально, но нужно закончить
В дизайн-референсе тема реально протянута только по части экранов.
Прежде чем это станет проблемой при вёрстке — вот точная карта, что уже
theme-aware, а что нет:

**Полностью на токенах (готовый образец для копирования паттерна):**
Dashboard (нижний белый sheet, карточки анкеты/активных задач/зоны
анализа), Settings (карточки, строки, сама строка переключателя темы,
карточка подписки), Profile (строки списка).

**Частично — только внешний фон экрана (`T.screen`), а карточки/текст
внутри всё ещё захардкожены под светлую тему:**
Filters (все 5 шагов), Results, University Details, Portfolio Upload,
Analysis Loading, Analysis Preview, AI Chat, Active Tasks, Vaults List,
Vault Detail, Achievement Log, Module Detail.
→ На этих экранах при переключении в тёмную тему сейчас «поедет» только
задний фон, а белые карточки/тёмный текст внутри останутся светлыми —
если открыть дизайн-референс в браузере и переключить тумблер, это будет
заметно. Это не баг для наших целей, а просто незаконченный проход —
при вёрстке RN-компонента дояпплять на нём тот же 7-токенный паттерн
(`card`/`border`/`ink`/`sub`/`chip`) по аналогии с Dashboard/Settings/
Profile, а не изобретать новый.

**Сознательно вне темы (фиксированный тёмно-синий «брендовый» фон
независимо от темы):**
Splash, Welcome, AuthLoading, Paywall, Focus, Payment, System-экраны
(Error/Offline/Maintenance/UpdateRequired). Похоже на осознанный выбор
дизайна — маркетинговые/переходные экраны держат фиксированный
брендовый навy вне зависимости от пользовательской темы (частый паттерн
в мобильных апах: онбординг/paywall не подчиняются theme-тумблеру).
Реализуем по умолчанию так же — навy-экраны игнорируют `theme` и всегда
рендерятся в фирменных `navy.primary` / `navy.deep`. Если по факту это
было просто не докрашено, а не задумано — легко исправить одной правкой
в токенах компонента.

## Цвета (не зависящие от темы — брендовые/навy экраны)
| Токен | Hex | Использование |
|---|---|---|
| `navy.primary` | `#2C317A` | Splash, Welcome, Dashboard верхняя навy-зона, UniversityDetails header, VaultDetail, Profile верх, ModuleDetail верх |
| `navy.deep` | `#151843` | Paywall, аватар бота в чате, Maintenance/Update |

## Акценты (общие для обеих тем)
| Токен | Hex | Использование |
|---|---|---|
| `accent.blue` | `#2E6BFF` | Основной интерактивный акцент |
| `accent.blueLight` | `#7C93FF` | Вторичный акцент на тёмном фоне |
| `accent.gold` | `#F3C24B` | Premium/достижения |
| `accent.green` | `#1FB574` | Success/выполнено |
| `accent.rose` | `#E2739B` | Ошибка/акцент |

## Радиусы
Официальная шкала: **14 / 20 / 24 / 32 px** для карточек/кнопок/модалок.
Мелкие элементы (иконки, чипы, чек-боксы): `radius.xs = 8px`,
`radius.sm = 12px`.

## Отступы
Не выровнены по строгой сетке в прототипе — нормализовать под 4px-базу
(`4/8/12/16/20/24/32/40`) при вёрстке, сохраняя пропорции «на глаз».

## Тени
`box-shadow` → `elevation` (Android) + `shadowColor/shadowOffset/
shadowOpacity/shadowRadius` (iOS):
- Карточки: `0 1px 2-3px rgba(20,24,60,.04-.07)`
- Крупные CTA: `0 14-18px 30-36px -12/-14px rgba(...)` в цвет кнопки

## Веб-контейнер (Фаза 5 — «не ломается на широком экране»)
Дизайн-прототип нарисован в телефонном фрейме: внешняя рамка `414px`,
контентная область `390px` (`design-reference.html:71–73`). На вебе
(`expo start --web` / `expo export --platform web`) на широком экране
приложение **не растягивается**, а живёт в центрированном app-like
контейнере:

| Токен | Значение | Назначение |
|---|---|---|
| `APP_MAX_WIDTH` | `420px` | Макс. ширина контентного столбца (экспортируется из `app/_layout.tsx`) |
| гаттеры по бокам | `theme.page` | Canvas-цвет за пределами столбца (тот же, что зона статус-бара) |
| боковые границы столбца | `StyleSheet.hairlineWidth`, `theme.border` | Тонкая отбивка столбца от canvas |

Применяется только при `Platform.OS === 'web'`; на iOS/Android рамка —
`flex: 1` без ограничения ширины. Абсолютные оверлеи (таб-бар,
офлайн-баннер, dev-меню) живут **внутри** этого столбца, поэтому тоже
ограничены `APP_MAX_WIDTH`.

Это НЕ desktop-раскладка — многоколоночная widescreen-компоновка
сознательно вынесена в отдельную Фазу 7 (`CLAUDE.md` §9,
`docs/00-roadmap.md`).

## Закрытые вопросы (были открыты в v0.1)
1. ~~Light/Dark тема~~ — **решено**: строим настоящий переключаемый
   theme, токены и обе палитры выше уже финальные, тянутся из дизайна.
2. ~~Веб-раскладка~~ — **отложено**, не вопрос дизайн-токенов сейчас.
   Десктоп-адаптация — отдельная фаза после готового мобильного
   фронтенда, см. `CLAUDE.md` §9 и `docs/00-roadmap.md` Фаза 8.
3. ~~Логотип/визуальная идентика AcademicSpace~~ — **закрыт (Фаза 0)**:
   пока используем градиентный ромб из дизайна как временный знак
   (`accent.blue → accent.blueLight`). Реализация — атом `<BrandLogo>`,
   который читает `constants/brand.ts → logo.mode` (`'diamond' | 'image'`).
   Когда появится брендбук: положить файл в `assets/brand/logo.png`,
   раскомментировать `logo.source` и переключить `logo.mode` на `'image'` —
   код экранов не меняется.
