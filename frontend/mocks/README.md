# mocks/

Централизованный мок-слой (Фаза 4 роадмапа). Не «данные на коленке» по
компонентам, а единая система.

## Файлы

- **`fixtures.ts`** — неизменные справочники; извлечены 1:1 из `renderVals()`
  дизайн-референса. Экраны читают статические каталоги отсюда напрямую
  (`CLAUDE.md` §3): списки опций, копирайт, дефолты форм.
- **`store.ts`** — единый персистентный Zustand-стор `useMockStore` =
  эквивалент `state` прототипа: анкета / фильтры / задачи / сообщения /
  оплата / копилки / **XP** / **журнал** / **офлайн-флаг**. Экраны дёргают
  его сеттеры для «стейта в моменте» (чек-боксы, выбор в фильтрах,
  офлайн-баннер). `resetMock()` возвращает всё к сид-состоянию (есть в
  DEV-меню).
- **`handlers/`** — по ресурсам (`auth`, `profile`, `questionnaire`,
  `universities`, `chat`, `analysis`, `tasks`, `vaults`, `subscription`,
  `achievements`). Читают/пишут `store.ts`, отдают ответ в форме
  `docs/api-contract.md` через `delay()`. Это **мок-ветка** адаптера.
- **`delay.ts`** — задержка, чтобы TanStack Query проходил через
  `isLoading`, как с реальным Flask.

## Адаптер-seam (`EXPO_PUBLIC_USE_MOCKS`)

Хуки `hooks/api/*` не импортируют `mocks/` напрямую — они ходят в
`services/api/<resource>.ts`. Там по `ENV.useMocks` (`constants/env.ts`)
выбирается реализация интерфейса `<Resource>Api`: мок-хендлер отсюда или
`services/api/http/*` (реальный `fetch` к `ENV.apiBaseUrl`). Фаза 8 =
дозаполнить `services/api/http/*`, `mocks/` при этом не трогается.

## XP и журнал реально текут

`store.ts.toggleTaskItem`: когда тап закрывает **последний** пункт модуля —
модуль удаляется из `tasks`, его `xp` прибавляется к `store.xp`, а в
`store.journalEntries` уходит запись (цвет точки — по виду модуля,
`fixtures.TASK_KIND_LOG`).

- `handlers/profile.ts` отдаёт `xp` из стора → кольцо XP на дашборде и
  профиле растёт;
- `handlers/achievements.ts` отдаёт `totalXp` из стора и домешивает
  динамические записи в начало дня «сегодня»;
- `hooks/api/useTasks.ts` при `completed` инвалидирует профиль и журнал.

Всё персистится (AsyncStorage) → прогресс демо переживает перезапуск.
`store.ts` версии `2`: `migrate` из `v1` добавляет `xp`/`journalEntries`,
не теряя остальной прогресс.

## Почему офлайн-флаг здесь, а не в `stores/`

`offline` — часть «состояния прототипа», поэтому живёт в `useMockStore`
(было в отдельном `stores/ui.ts`). Но, в отличие от прочих полей, он
**не персистится** (`partialize` его не включает): грузиться в фейковый
офлайн после перезапуска не нужно. `resetMock()` его тоже сбрасывает.
